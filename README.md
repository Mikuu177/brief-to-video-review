# Brief to Video Review · 审阅台

将营销 Brief 转成可回源的审核规范，再审核创作者脚本与完整视频。AI 给出候选问题和时间证据，由人确认最终结果。

**默认本机单用户，打开即用，无需注册或登录。** 仓库不包含 API Key、客户素材、私有审核结果或线上账户。所有模型调用使用你自己的配置。

## 能做什么

- 导入 PDF、DOCX、TXT Brief；读取原文、页/区域、独立 OCR，生成可回查 Markdown。脚本还支持 XLSX 与旧 DOC（旧 DOC 版面可能不完整）。
- 提取规则、编辑适用范围、检查冲突；冻结后修改产生新版本，旧审核保留原依赖。
- 审核脚本并绑定 Brief 引文与脚本位置。
- 将原始 MP4、完整音轨与连续视频片段交给多模态模型，结合独立 ASR、事实/实体/解释和多轮对账生成内容档案。
- 检查产品展示、文字可读性、颜色外观、背景干扰及特效；疑似问题做连续片段复核，点击时间回放。
- 异步任务、阶段检查点、有限重试、取消、人工裁定与 HTML/JSON 报告。

## 快速开始：Docker

需要 Python 3（生成本机配置）、Docker Engine 与 Compose。

```bash
git clone https://github.com/Mikuu177/brief-to-video-review.git
cd brief-to-video-review
cp .env.example .env
python3 scripts/init_env.py
docker compose up --build -d
```

打开 <http://127.0.0.1:8008>，直接进入空工作空间。Docker 会启动 Web/API、PostgreSQL、Redis、Worker 和恢复进程；初始化脚本创建内部工作空间记录以保留审计外键，不要求用户登录。若8008已占用，在`.env`设`REVIEW_BIND_PORT=8010`。

没有模型 Key 时，可以上传/查看来源、建立人工草案和处理版本；自动审核会明确显示待配置，不生成假结果。在`.env`配置你自己的模型和存储后，重建服务配置：

```bash
docker compose up -d --force-recreate api worker recovery
```

API Key只由服务端读取，禁止放到前端或提交Git。说明见[配置指南](docs/CONFIGURATION.md)。

## 使用顺序

1. 新建项目，设置产品、平台与活动阶段，上传自己的 Brief。
2. 先检查来源完整性，核对待处理区域，再提取/编辑规则、确认范围并冻结。
3. 上传脚本，查看逐条候选反馈和原文出处。
4. 绑定脚本和原片，读取视频内容、运行成片及视觉专项，按时间回放证据。
5. 人工确认，导出报告。本项目不包含视频发布功能。

## 边界

读取任务结束、结构对账一致、OCR有文字，不等于条款提全或识别正确。大文件有明确的页数、内存、CPU和任务时限，超限或漏页会阻塞，而非标成成功。

模型接收完整/连续MP4，并非应用抽取几张图代替视频；供应商仍按2/5fps等参数预处理，瞬时信息可能遗漏。视觉复核支持“出现遮挡”等事实，也不自动证明违反Brief；审美建议不应变成新增硬性要求。

复读模型不等于独立人工金标准。没有标注集就不宣称准确率或零遗漏，自动通过门槛默认关闭。当前是供社区使用与改进的技术试审系统。

默认无鉴权单用户，仅监听本机。不要直接将它暴露到公网或接入已有私有数据库。多人/公网部署应使用独立实例、TLS和可信鉴权网关；保留的`AUTH_MODE=session`是可选扩展，非默认要求。
